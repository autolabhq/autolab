## Kernel construction

The R61 multiplication map has a three-dimensional kernel in the tensor space
`F_193^3 tensor F_193^3`. For any three independent left factor sections,
write their columns as `X`. Every kernel matrix has a unique decomposition

```text
K = X Y^T.                                         (1)
```

The first row of `Y^T` depends linearly on the projective kernel coordinate.
When that `3 x 3` map is invertible, choosing a smooth first right factor
determines `K` and forces the other two right factors by one linear solve.
Thus a candidate relation is generated by:

1. choosing three pairwise-disjoint smooth left sections with invertible `X`;
2. enumerating one smooth right section;
3. solving for `K` and the two forced right sections; and
4. testing smoothness and all divisor-disjointness conditions.

No product-pair secant scan or field-element scan is needed after the smooth
factor catalogs are available. The report pins all eleven loaded P1553 source
dependencies, not only the directly imported R65 module.

## Exact B=24 scan

The R63 base has 56 and 84 smooth factor sections. Of `C(56,3)=27,720` left
triples, 13,872 are pairwise disjoint and 13,795 are also invertible. Every one
of their first-row maps is invertible. R66 tests

```text
13,795 * 84 = 1,158,780                          (2)
```

first-right candidates, compared with R65's 7,021,878 smooth-product pairs.

The exact filters give

```text
all three forced right factors smooth: 569,
forced right factors pairwise disjoint:   1,
internally simple three-product sets:     1,
primitive relation candidate visits:      1,
distinct primitive lines:                 1.      (3)
```

Across the 13,795 left matrices, 13,231 have no smooth completion, 559 have
one, and five have two. Only one left matrix has any pairwise-disjoint right
completion. The generated Plucker key and all three product sections equal the

Its kernel coordinate is `(61,14,55)` and its full-rank kernel matrix is

```text

[92   0  61 ]
[14  55   0 ].                                    (4)
```

The unnormalized three product sections sum to zero because (4) lies in the

## Cost boundary

Let `S` denote the number of smooth factor sections in one class. For a random
invertible `X`, enumerating `S` first-right choices and requiring the two
forced rows to be smooth gives modeled hits `S^3/|P^2(F_p)|^2` per `X`.
Expected candidate work per relation is therefore

```text
|P^2(F_p)|^2 / S^2.                               (6)
```

With `p` comparable to subgroup order `N` and random fixed-sum point bases,
`S` scales as `B^3/N`, so (6) is `(N/B)^6`; collecting `B` rows is
`N^6/B^5`. This recovers the R63 uniform-model exponent rather than improving
it.

The full exhaustive R66 scan costs `C(S_left,3)*S_right`. For balanced
catalogs this is `Theta(S^4)`, the same asymptotic order as all pairs of
`M about S^2` smooth products. The toy candidate ratio is about 0.165, a
constant-factor reduction only.

Smooth factor-catalog construction, inherited R61 preprocessing, relation
rank, projected scalar logs, factor-base linear algebra, and target descent
remain uncharged. In addition, the executable materializes all subgroup points
from their scalar labels using `N` independent double-and-add multiplications,
then sorts them. The literal cost is `Theta(N log N)` public group operations
plus `O(N log N)` sorting, and it creates an invertible scalar-labelled lookup
table. It is not an inverse-DLP call, but it already exceeds the generic
square-root target and therefore cannot be hidden inside an unconditional
public-generator claim.
